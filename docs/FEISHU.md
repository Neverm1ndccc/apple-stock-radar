# 飞书群通知（v0.6.0）

1. 在你要接收提醒的飞书群添加「自定义机器人」，复制 Webhook；可使用只有自己的群。
2. 在库存雷达「设置 → 飞书群机器人」保存 Webhook。机器人启用签名校验时同时填写签名密钥；未启用时留空。若使用关键词校验，将关键词设为“库存雷达”。
3. 点击「测试飞书消息」，在飞书确认收到后开启「飞书通知」。
4. 回到「我的关注」，为需要的 SKU × 门店勾选「飞书有货提醒」。每个关注独立选择，默认关闭。

v0.3.2 支持一键批量设置：先点「全选当前结果」或勾选多个卡片，再点「开启飞书提醒 / 关闭飞书提醒」。可先按型号、地区、状态或分组筛选，全选只影响当前结果。批量选择不改变全局开关；仍需完成上方机器人配置并开启飞书通知。

自动发送首次有货、无货变有货、未知/过期后恢复有货的提醒，并遵守已有首次/恢复提醒设置。持续有货不重复发送；模拟数据不投递。打开开关不会补发旧观测或旧消息。

「发送到飞书」手动推送该关注的当前记录，包含产品、规格、门店、来源、观测时间与官网链接；不会额外查询 Apple 或改写库存历史。来源失败、未知和过期会明确标识，不能被手动发送伪装为有货。

关闭全局或某个关注的飞书开关会取消相应的待发送提醒。已经开始的发送无法撤回。暂停/移除目标也会取消待发送提醒。发送失败会记录为失败，不盲目重发；服务端确认接收不保证飞书客户端必然展示。

v0.6.0 按用户要求改为应用内直接保存：Webhook 和可选签名密钥存本机应用目录的 `private/feishu-credentials.json`，目录0700、文件0600，仅当前账户可读，文件未加密。普通查看配置、启用、手动/自动发送均不访问钥匙串，因此不会逐条索取系统密码。字段保存成功后清空、不回显；不进入日志、SQLite、导出或数据库备份。

升级不会自动读取旧钥匙串：可以在设置直接填写并点「保存到本机」，或主动点「从旧钥匙串导入（一次）」。只有导入命令读取旧Keychain，系统可能要求一次授权；导入后发送使用本机文件。旧Keychain项保留，界面的移除只删除本机配置。没有本机配置时自动飞书投递不领取队列，也不会自动回退读取钥匙串。

更换或导入配置会关闭全局飞书并取消旧待发队列，保存后重新开启；每目标选择保持。输入空签名密钥会清除此前签名。备份不包含凭证，换电脑或重新配置时需要另行保存；恢复数据库仍关闭飞书，避免旧消息误发。Bark继续使用钥匙串，本轮不更改其配置。

数据库升级为 v3，保留现有关注、扫描配置、预算和历史；打开 v1/v2 库前生成 pre-v3 备份。旧版 SQLite 备份恢复时会升级并关闭全局飞书通知，保留每个关注的选择，不自动重发。

按[飞书官方自定义机器人指南](https://open.feishu.cn/document/client-docs/bot-v3/add-custom-bot)实现文本消息、可选 HMAC-SHA256 签名与成功码校验。仅允许 `open.feishu.cn` 官方 HTTPS Webhook，禁止重定向；共享串行发送间隔至少 700ms，请求体最多 20 KB。消息含“库存雷达”，兼容关键词校验。默认禁用，没有配置实际机器人时不会外发。

协议、签名、去重、目标选择、取消待发送消息、来源隔离、脱敏及数据升级通过离线回归。实际群接收需要用户配置自己的机器人后完成，不使用开发者机器人代发测试。

## 扫描停用提醒

设置中的「停扫时通知飞书」默认关闭。开启且全局飞书已启用后，真实拒绝、限流或响应异常导致停扫时，发一条含原因、HTTP 状态、北京时间及人工恢复说明的消息。此为整个扫描来源故障，独立于每目标有货提醒，不逐目标重复发送。设置页显示最近故障消息状态。

故障提醒先原子领取为 SENDING，网络调用期间不持有数据库锁；完成后按同一事故 ID 条件确认，不能覆盖新事故。失败不盲目重发，重启/恢复取消旧 PENDING、将中断 SENDING 标为 UNCERTAIN。关闭全局通知、故障通知、暂停或切换来源会取消旧待发提醒；手动恢复扫描也不补发旧事故。

历史版本因每次调用钥匙串可能反复弹出授权。v0.6.0 的正常飞书流程已经移除此依赖；仅主动导入旧配置时可能出现授权。不要把Webhook发到聊天，也不要放宽旧钥匙串ACL。

2026-10-25 历史补充：后台扫描与通知投递使用独立任务，旧版钥匙串读取在 blocking 线程执行，通知等待系统授权不能阻塞下一批库存扫描。新增并发回归验证通知不完成时扫描仍连续运行；Rust 测试总计 65 项。
