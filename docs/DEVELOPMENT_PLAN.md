# Apple Store 库存雷达：开发与验收计划

日期：2026-10-24\
状态：用户已确认推荐方案；本地手动/模拟 MVP 已实施，当前结果见 TEST_REPORT.md\
依据：用户提供的《Apple Store 库存雷达 macOS 个人版 PRD v1.0》

## 1. 建议确认的实施方案

1. **技术路线**：Tauri 2 + Rust + React/TypeScript + SQLite。基于 Apple Pickup Watcher 做本地派生改造，保留 GPL-3.0-or-later、NOTICE 和归属；不在本轮创建远程 fork 或发布代码。主要复用目录、选择组件与桌面基础，不直接沿用其所有查询、配置和告警行为。
2. **交付顺序**：先完成可运行的本地 MVP，包含手动记录和明确标识的模拟演示。自动源作为独立工作包；仅在来源、许可、调用节奏及中港可用性验证通过后接入。未通过时交付名称与说明明确为本地库存关注助手，不能算实时自动监控完成。
3. **首批目录建议**：保留中港地区和多品类模型，优先验证 iPhone 的型号、容量、颜色和门店流程；iPad、Mac、Apple Watch 随后补充经过核验的目录和组合规则。此项为对 PRD 的分批建议，需用户确认。
4. **运行与分发**：首期面向当前 Apple Silicon Mac 本地自用，中文界面，适配亮/暗模式。先交付本地 `.app`，条件允许再提供 `.dmg`；签名、公证、Intel 兼容验证和自动更新不在首轮承诺内。

用户已于 2026-10-24 确认以上推荐方案。后续章节保留原始分阶段规划，实际进度以 task_plan.md 和 TEST_REPORT.md 为准。

## 2. 当前基线与已发现的依赖

- 工作区没有现有应用代码，可以直接以当前目录作为项目根，避免多套嵌套 Git 仓库。
- 本机为 macOS 26.6.2 / arm64，已配置 Xcode；Node 26 和 npm 可用，Rust/Cargo 尚未检测到。
- 上游已有 Rust workspace、Tauri 2、React 19、目录、三态模型、托盘和通知基础；其 Cargo.toml 声明最低 Rust 1.98，需在实施时核验可安装版本。
- 上游默认自动查询、代理切换、在线目录刷新和普通设置中的推送地址保存，与本 PRD 有差异，需要隔离或替换。
- 当前只做了文档、清单和部分代码抽查，没有构建上游，没有实测 Apple 接口，也没有获得数据访问许可的正面证据。
- 技术路线的最终可复用程度在阶段 0 通过构建和代码审查确定。如果无法合理复用，先说明证据和替代方案，再确认是否切换 SwiftUI 或全新工程。

## 3. 阶段与任务

### 阶段 0：工程与来源尽调

**任务**
- 锁定上游 commit，检查适用 AGENTS.md、许可证、NOTICE、依赖和构建说明。
- 准备受支持的 Node/Rust 工具链，优先使用已有版本或用户级安装，记录版本与锁文件。
- 构建不发起库存请求的基线，核对托盘、目录、通知、配置与测试现状。
- 列出保留、替换、停用模块；明确自动请求、在线目录更新、代理和自动打开购物袋的处理范围。
- 形成来源矩阵：提供方、许可依据、地区范围、允许机制/配额、拒绝与限流处理、验证结果。

**交付**：`ARCHITECTURE.md`、`DATA_SOURCE_ASSESSMENT.md`、`TEST_PLAN.md`、可构建的基线、依赖和许可证记录。

**验收**：明确复用方案；没有未经配置就启动的外部库存请求；自动源标为 GO / 待证据 / NO-GO，不能以开源许可代替数据访问许可。

### 阶段 1：macOS 菜单栏与窗口骨架

**任务**
- 菜单栏图标、运行/暂停/异常标识、左键卡片、右键启停/设置/退出。
- 约 380 × 540 的卡片，支持筛选、摘要与主窗口入口；尺寸根据系统缩放调整。
- 主窗口提供关注、新增、历史、设置、诊断页面骨架。
- 关闭卡片或主窗口不结束后台任务，显式退出才终止；默认隐藏 Dock 图标。
- 检查多显示器、失焦收起、亮暗模式和基本键盘/VoiceOver 标签。

**交付**：可以启动与退出的本地应用，带明确标识的演示状态。

**验收**：不用浏览器即可通过菜单栏打开；关闭窗口后菜单栏仍可用；暂停与退出语义正确。

### 阶段 2：目录、关注与 SQLite

**任务**
- 建立带版本和来源的中港目录；核验首批 SKU、官方产品链接及门店标识。
- 地区 → 类别 → 型号 → 容量/颜色 → 城市/门店 → 组合预览 → 保存。
- 只组合真实存在的变体；跨地区组合拒绝，重复目标去重，解释跳过原因。
- 支持关注暂停/恢复/删除/优先级、全部启停和逻辑分组。
- 建立 migration、目标、观测、事件、通知投递与设置表；数据库写入串行化。
- 规范分组关系：精确目标 `(variant_id, store_id)` 唯一，分组与目标用成员表关联，允许同一目标出现在多个组且只观测一次。
- 所有时间存 UTC；前端只接收脱敏 DTO，不持有凭证。

**交付**：可创建和管理真实关注目标，保存后重启可恢复。

**验收**：2 个有效 SKU × 3 家店产生 6 个目标；再次添加不增加精确目标；中港不串号；删除关注的历史保留策略有明确说明。

### 阶段 3：来源接口、状态、通知与本地 MVP

**任务**
- 定义 `AvailabilityProvider` 和统一观测协议，实现 ManualProvider、MockProvider；自动源只有通过门槛才实现启用。
- 手动检查为用户打开官方页、查看后录入有货/无货；单击“手动检查”本身不表示应用已经读到官网库存。
- 实现可信三态和 PENDING/STALE/UNSUPPORTED 展示语义；失败显示 UNKNOWN，保留最后有效状态供历史查看。
- 固定事件语义：连续有效无货 → 有货为补货事件；首次有货和未知后恢复有货分别命名；连续有货不重复提醒。
- 未知后恢复有货优先记录恢复事件，不额外推断未知期间发生补货；通知开关独立可配。
- 模拟数据、手动记录、未来自动观测分开标识；模拟状态默认不污染真实历史或触发真实渠道，用户主动测试可发送带“测试”标记的通知。
- 建立幂等事件与投递记录；定义崩溃恢复和重试策略，避免把“尽量不重复”误写为外部推送严格 exactly-once 保证。
- 系统通知授权、测试、点击行为；Bark 默认关闭，配置后测试，Keychain 保存凭证，推送失败隔离。
- 官方跳转只允许 HTTPS 与精确白名单主机/受信任子域，拒绝伪后缀、带凭证链接和任意跳转 URL。
- 调度器支持取消、合批、去重、超时、退避、暂停和唤醒恢复；模拟调度和真实源调度清晰区分。
- 真实源被阻断/未授权/限流时停止该源自动请求，人工处理；不直接照搬上游自动换线路或持续探测。

**交付**：包含目标管理、持久化、手动记录、模拟演示、Mac 通知、Bark 与基础历史的完整本地 MVP。

**验收**：PRD TC-001～TC-011、TC-014～TC-015 对应场景通过；Bark 有真实凭证时验证端到端投递，缺少凭证时只能记为待用户验证。

### 阶段 4：历史分析与数据管理

**任务**
- 时间线、24 小时/7 天/30 天筛选、SKU/门店筛选、首次/末次有货观测与有效次数。
- 7/30 天热力图同时显示有货观测比例、有效样本量与查询成功率；UNKNOWN 不进入有货比例分母。
- 连续有货观测区间标注采样空洞，避免把观测时间当作精确放货/售罄时间。
- 脱敏 CSV/JSON 导出、诊断日志和备份；保留期 7/30/90/180 天，默认 90 天。
- 数据清除有明确界面确认；登录时启动默认关闭，由用户启用。
- 按确认范围补齐其他品类，验证配件组合等特殊规则；没有验证的 SKU 不冒充有效目录。

**交付**：完整历史页、热力图、导出清理、登录启动设置。

**验收**：TC-012～TC-013 通过；已知样本手算与统计一致；模拟数据不混入真实统计；备份恢复可用。

### 阶段 5：系统验收、稳定性与交付

**任务**
- 执行 Rust 单元/集成测试、目录与解析契约测试、前端关键逻辑测试和 macOS 手动冒烟测试。
- 验证退出重启、断网、睡眠唤醒、通知权限拒绝、Bark 故障、迁移与数据库错误。
- 对模拟/手动来源完成本地稳定性观察；如自动源已获准，再按许可验证真实源长时运行。
- 24～72 小时稳定性记录单独列为实际观察任务；短时间测试不能替代这项结果。
- 测量当前设备的内存、CPU 和唤醒次数，记录环境；200 MB 是目标，不作为未测量的结论。
- 本地构建 `.app`，条件允许生成 `.dmg`；提供 README、安装/使用说明、已知限制和验收报告。

**验收**：能在当前 Mac 使用；构建可复现；验收报告分别列出已通过、待用户验证、待外部条件和未完成项。

## 4. 自动源独立工作包

**进入条件**：阶段 0 得到可支持自动访问的正面证据，且来源定义明确。缺少许可不能通过更换技术路径自动补足。

**实施步骤**
1. 验证提供方、许可范围、认证方式、配额及大陆/香港覆盖。
2. 对中港各选经核验的 SKU/门店做最小样本契约验证，保留脱敏 fixture 与核验记录。
3. 实现 provider，接入统一状态机，验证缺失、超时、拒绝、限流和错误解析。
4. 验证停止/恢复策略和按授权上限调度，记录实际时效及数据缺口。
5. 通过验收后才开放自动模式并说明 Mac 在线/唤醒依赖。

**退出结果**
- GO：可以在确认的范围内启用自动源。
- 待证据：保留接口与手动/模拟能力，不声称自动监控完成。
- NO-GO：停用该来源，记录原因；不靠代理轮换、指纹伪装或验证码绕过继续。

## 5. 依赖与推荐顺序

`阶段 0 → 阶段 1 → 阶段 2 → 阶段 3（本地 MVP）→ 阶段 4 → 阶段 5`

自动源评估从阶段 0 开始；适配依赖阶段 3 的 provider/状态协议。没有获准自动源不阻断本地工作，但阻断“实时自动库存监控完成”的结论。

阶段 3 完成时先提供可运行版本让用户体验；后续按已确认计划继续推进。除范围变化、外部条件或真实设备权限需要用户操作外，不为每个内部技术细节反复请求确认。

沿用 PRD 的单人初估：阶段 0～5 分别为 2–4、3–5、4–6、5–7、4–6、3–5 个工作日，总计 21–33 个工作日。当前尚未完成基线构建，不能据此承诺交付日期；复用程度确认后再调整。自动源许可等待及适配耗时另计。
