# 库存雷达 · macOS 个人版

Tauri 2 + Rust + React 的本地 Apple Store 关注助手，支持中国大陆与中国香港的离线 iPhone 目录。

当前提供**手动记录与离线模拟**，支持用户明确启用个人 Apple 非公开接口查询，并设置扫描间隔。v0.4.0 增加标准 HTTP/2、低频连接保护、响应复用及停扫飞书提醒。新安装默认关闭，启用不代表 Apple 授权；拒绝或限流立即停止。目录是上游离线快照，规格、门店和库存均需在 Apple 官网自行核对。

## 使用

1. 打开本机构建的 `target/release/bundle/macos/库存雷达.app`。
2. 选择「添加关注」，按地区、型号、容量选择 SKU 与门店，查看组合数并保存。重复的 SKU × 门店自动去重。
3. 在关注卡片点击「官网检查」，亲自查看供货情况，再「录入结果」。无法确认时选择未知及原因。
4. 在「设置」切换为模拟演示后，可回到关注页「演示一轮」。模拟与手动数据共用目标，各自保存状态和历史；模拟观测不会产生真实通知。
5. 「历史分析」可点击“只看有货”，按库存状态、地区、型号/容量/颜色/SKU/门店关键字、观测事件、关注目标及自定义时间组合筛选；支持24小时/7天/30天预设和重置。统计及小时热力图按筛选结果同步更新。CSV/JSON 导出当前来源的全部保留观测，不受页面筛选或 5000 条列表上限影响。

v0.3.1 起作为普通 macOS App 显示在 Dock 和 ⌘Tab 中，可直接切回应用。关闭主窗口会隐藏窗口并继续后台运行，点击 Dock 图标可重新打开；最小化后重新打开会恢复主窗口。左键菜单栏图标打开小卡片，右键可打开主窗口、设置、暂停或退出。Mac 休眠期间不执行扫描；退出应用停止本地任务。登录启动默认关闭，可在设置中启用。

本地数据位于 `~/Library/Application Support/local.dingdingguo.stockradar/`，可在设置中打开。数据库与上游应用隔离。移除关注会保留历史，重新添加可恢复；清空历史仅影响当前来源。备份包含目标、设置与两种来源的历史。恢复前会自动备份当前库，校验失败保留原库；恢复后关闭 Bark 和后台模拟，不自动重发待投递消息。

## 通知

v0.3.0 新增飞书群机器人：在「设置 → 飞书群机器人」保存 Webhook 和可选签名密钥、测试并开启全局通知，再为各关注勾选「飞书有货提醒」。也可点击卡片的「发送到飞书」推送当前状态。v0.6.0 起配置可保存到本机私有文件，发送不再逐条访问钥匙串；旧配置可主动一次导入。默认不发送；[配置说明](docs/FEISHU.md)。

v0.3.2 可在关注列表勾选多个目标，或点击「全选当前结果」，批量开启/关闭飞书提醒、暂停/恢复关注、调整优先级。搜索或筛选后，全选只覆盖当前结果；更改筛选会清空选择。批量操作不改全局通知配置，也不补发旧提醒。

系统通知默认关闭，开启时请求 macOS 权限。Bark 默认关闭，首版支持 `https://api.day.app/你的Key`；地址只存 macOS Keychain，不会回显，也不在 SQLite、日志和导出文件中保存。启用 Bark 后会向该服务发送产品与门店摘要。

首次有货、连续无货变有货、未知或过期后恢复有货为不同事件。相同观测 ID 幂等；持续有货不重复提醒。模拟观测不向真实渠道投递，「测试通知」会显式标注测试。投递结果表示系统或服务接收，不能保证设备最终展示；外部推送不承诺严格 exactly-once。

## 开发与离线检查

需要 macOS、Xcode Command Line Tools、Rust 1.98+（本机 1.99.1）、Node 24+、pnpm 9.15.9。

```sh
pnpm install --frozen-lockfile
pnpm tauri dev
```

```sh
cargo test --offline
cargo fmt --all --check
cargo clippy --offline --all-targets -- -D warnings
pnpm build
pnpm test
```

本机默认 pnpm 是环境包装器，若包装器尝试重装依赖，可用 `npx --yes pnpm@9.15.9` 替代命令中的 `pnpm`。本机 Rust 可执行文件位于 `~/.cargo/bin`，需在 PATH 中。

```sh
pnpm package:macos
```

浏览器界面验收使用隔离的 IPC harness，fixture 由 Rust 内存数据库生成，不读取用户数据库：

```sh
cargo run --offline -q -p radar-core --example ui_fixture > tests/.ui-fixture.json
pnpm dev
# 打开 http://localhost:1420/tests/ui.html
# 空态加 ?empty=1；菜单栏布局加 ?view=tray
```

该测试页面不会进入生产包。验证记录见 [TEST_REPORT.md](docs/TEST_REPORT.md)，架构与来源边界见 [ARCHITECTURE.md](docs/ARCHITECTURE.md) 和 [DATA_SOURCE_ASSESSMENT.md](docs/DATA_SOURCE_ASSESSMENT.md)。

## Apple 扫描间隔

在设置页可预设 5–86400 秒的整数间隔，默认 300 秒。每个间隔查询一个按地区/门店合并的批次；来源最低间隔、失败退避与累计预算优先。应用最多暂存 6 次额度，每 60 秒恢复 1 次，不能通过立即扫描、重启或恢复备份重置。此预算是应用保护策略，不是 Apple 的官方配额。

先开启“个人使用非公开库存接口”，切换到 Apple 模式，再开启后台扫描。来源被拒绝后立即停扫，保护等待依次为 5/10/20/30 分钟，并遵守服务端 Retry-After；等待结束仍需人工恢复，不自动探测。接入边界、迁移及测试范围见 [APPLE_SCANNER.md](docs/APPLE_SCANNER.md)。

v0.2.3 可直接在「我的关注」、菜单栏小窗口或设置页点击「启动扫描 / 关闭扫描」。关闭后不再发送后续请求，已发出的请求等待结束；启动保持原有的间隔、预算与保护等待。关注页同步显示已关闭、扫描中、下次扫描或停扫原因。

v0.2.4 修复后台菜单栏刷新与界面读取数据库并发时可能出现的死锁，升级保留现有关注、设置、预算与历史。

v0.4.0 使用独立连接池并协商标准 HTTP/2（服务端不支持时回落 HTTP/1.1）。开启「低频连接保护」后每批至少等待 180 秒，保留原扫描间隔；这是降低请求压力的可选配置，不能保证消除服务端拒绝。优先扫描最久未更新的目标；只复用响应明确返回的已关注门店和请求 SKU，不推断缺失库存。

「停扫时通知飞书」可在拒绝、限流或响应异常停扫时发送一次故障提醒，需要飞书全局开关和可读的 Keychain 配置。两项新开关默认关闭。若逐店完整覆盖超过记录有效时间，设置页会提醒可能过期；例如 6 批 × 180 秒约 18 分钟，响应复用是否缩短需以实际返回为准。

v0.4.1 修复网络失败退避期间关闭扫描后无法重新开启的问题。可先开启定时扫描，实际请求仍等待下次重试时间；拒绝或限流造成的来源停扫仍须保护等待结束后人工恢复。

## 当前限制

- Apple 非公开接口可能拒绝访问或变更，实际请求可能只得到 UNKNOWN；离线目录尚未在线核验，不承诺实时或稳定可用。
- 首批仅展示 iPhone；其他品类、独立连续区间图、自定义时间范围与更完整的分组规则待后续开发。
- CSV/JSON 是供分析的导出，恢复使用 SQLite 备份；暂不支持外部目标配置导入及应用内一键擦除全部文件。
- 系统通知实际展示、Bark 手机端接收、登录启动、睡眠唤醒、多显示器与 24–72 小时稳定性需分别实测。
- 本机包面向 Apple Silicon，尚未开发者签名或公证；Intel 与公开分发未验证。DMG 使用 hdiutil 构建，避免 Finder 自动排版超时。
